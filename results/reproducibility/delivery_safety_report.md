# Clean delivery branch safety check

The local `delivery/reproducibility-safe` worktree was created directly from `origin/main`. It does not contain a merge or cherry-pick of the six endpoint-bearing `work` commits. The nine historical Qwen JSON originals remain in the separate local `work` checkout. Their copies under `qwen_historical_public/` are labeled as redacted, and `qwen_historical_sha256.csv` records both original and public-copy hashes. The raw `results/qwen_input_length_sensitivity/source_verification.json` is excluded and explicitly ignored.

A read-only text scan of the **entire prepared worktree** (322 files at the time of this check, excluding Git metadata and Python/pytest caches) found no workspace-dedicated URL, workspace ID pattern, `sk-` key pattern, Bearer value or URL-embedded account/password. No `.tex`, PDF or file over 40 MB was present. All nine Qwen public copies were independently compared with their local originals after the specified redactions; their SHA-256 pairs matched the manifest. Seventy copied prediction, metric and threshold JSON/CSV/JSONL files were byte-identical to the historical workspace.

Four inherited files from `origin/main` still contain a Windows user path: `reports/mojibake_label1_summary.json`, `reports/mojibake_summary.json`, `reports/processed_data_summary.json`, and `supplementary_202610/tfidf_logreg/config.json`. Twenty-six files contain ordinary historical `/root/` or `/home/` paths. These are location disclosures, not API credentials; they were not newly imported from `work` or altered because they are historical records already present on `main`. Review them separately if the project later adopts a zero-personal-path publication rule.

The provider's shared Beijing endpoint is the public client fallback. Historical Qwen runs used a workspace-dedicated endpoint; the two routes are documented as different. Runtime credentials remain read from `DASHSCOPE_API_KEY`, and the optional actual endpoint is read from `QWEN_BASE_URL`. Public configuration serialization contains an endpoint category and SHA-256 instead of the URL. Transport errors redact the configured URL and key before recording an error string.

The system Python installation could not collect Qwen tests because PyTorch failed to load `c10.dll` (`WinError 1114`). The existing CPU virtual environment in the historical checkout imported PyTorch successfully; using it, 37 targeted, offline Qwen tests passed. AST parsing and an isolated, transport-free check of `QwenConfig` environment lookup, public serialization and error redaction also passed. No model inference or API request ran.

The original public `work` branch still exposes the historical workspace endpoint in its Git history. This new branch does not remove that earlier exposure. No `git add`, commit, push, history rewrite, deletion or branch merge occurred during this preparation.
